# 📌 Project: Plimo (AI 기반 사용자 감정 맞춤형 음악 추천 서비스)

## ✅ Project Summary
* **기간:** 2025.09 - 2025.12
* **성격:** 비정형 텍스트 감정 분석(AI) 및 오디오 피처 매핑 기반 사용자 맞춤형 음악 추천 웹 서비스
* **주요 역할:** Full-stack Developer & Backend Architect (Spring Boot ↔ Flask AI 서버 오케스트레이션, ETL 파이프라인 구축, CI/CD 배포)
* **기술 스택**
  * **백엔드 & AI:** Java 17, Spring Boot, Python, Flask, KLUE-RoBERTa-large (AI Model)
  * **프론트엔드:** Thymeleaf, JavaScript, HTML5/CSS3, Bootstrap
  * **데이터베이스 & ETL:** MySQL (Spotify API / Track Analysis 기반 오디오 피처 ETL 파이프라인)
  * **인프라 & DevOps:** AWS EC2, GitHub Actions (CI/CD 자동화)
  * **협업 및 관리:** Jira (Agile/Kanban), Notion (ADR 문서화)

---

## ✅ 주요 서비스 특징 (Key Features)

> 🧠 **비정형 텍스트 기반 10가지 감정 라벨 정밀 분류**  
> 사용자가 입력한 문장에서 파인튜닝된 AI 모델(KLUE-RoBERTa)을 통해 10가지 세부 감정 라벨을 실시간 분석 및 추출

> 🎵 **7가지 오디오 피처(Audio Features) 매핑 추천 엔진**  
> Energy, Valence, Acousticness 등 7가지 음원 파라미터를 파이프라인으로 연동하여 감정 분석 결과에 최적화된 음원 정밀 필터링

> ⚡ **20만 건 규모의 독자적 음원 데이터베이스 보유**  
> 외부 API 의존성을 탈피하기 위해 Spotify 및 Track Analysis 연동 ETL 파이프라인을 구축, 203,000건의 음악 데이터셋 적재

> 🔄 **Spring Boot - Flask 이종 서버 오케스트레이션**  
> 메인 백엔드(Spring Boot) 서버와 AI 추론(Flask) 서버 간의 분산 통신 파이프라인을 설계하여 데이터 흐름의 안정성 확보

---

## ✅ 기여한 부분

### 1️⃣ Spring Boot ↔ Flask(AI) 이종 서버 통신 및 백엔드 파이프라인 설계
* 사용자의 입력 문장을 AI(Flask) 서버로 전달하고, 반환된 10가지 감정 라벨을 DB 필터링 파이프라인과 연동하는 백엔드 오케스트레이션 구축
* Spotify 7가지 오디오 피처(Energy, Valence 등) 파라미터 조건절 쿼리를 설계하여 감정 분석 결과와 음악 데이터 간 정교한 매핑 로직 구현

### 2️⃣ 외부 API 의존성 극복을 위한 20만 건 규모 ETL 파이프라인 구축
* Spotify API 정책 변경으로 인한 데이터 공급 차단 이슈 발생 시, Exportify 및 Track Analysis API를 조합한 데이터 추출 ETL 파이프라인 설계
* 약 203,000건의 오디오 피처 및 트랙 상세 속성 데이터를 수집·정제하여 MySQL DB에 적재함으로써 서비스 데이터 가용성 및 독립성 확보

### 3️⃣ GitHub Actions 기반 CI/CD 파이프라인 자동화 및 인프라 운용
* AWS EC2 인프라 환경 구축 및 GitHub Actions를 활용한 자동화된 CI/CD 배포 파이프라인 구축
* Main 브랜치 코드 Push 시 Gradle 빌드 및 서버 자동 재배포 환경을 구현하여 수동 배포 리스크 제거 및 배포 소요 시간 단축

### 4️⃣ API 규격 사전 정의 및 애자일(Agile) 병렬 개발 체계 주도
* FE-BE-AI 간 REST API 명세서 사전 정의 및 ADR(Architecture Decision Records) 작성을 통해 파편화된 기술 결정 근거 단권화
* Jira 기반 Sprint/Kanban 관리 체계를 도입하여 파트 간 업무 중복 및 병목 현상을 방지하고 개발 생산성 향상

## ✅ 트러블 슈팅

### 1️⃣ 외부 API 정책 변경에 따른 데이터 공급 차단 위기 극복 (ETL 파이프라인 구축)
* **문제 배경:** 프로젝트 진행 중 Spotify API 정책 변경으로 인해 핵심 데이터인 '오디오 피처' 수집 경로가 차단되며 추천 서비스 마비 리스크 발생
* **원인 분석:** 외부 단일 API 의존도가 높아 정책 변경 및 접근 제한 시 서비스 가용성이 완전히 손상되는 구조적 한계 존재
* **해결 방안:** Exportify 및 Track Analysis API 연동을 통합한 자체 ETL 파이프라인을 구축하여 음악 상세 속성 데이터 직접 추출 및 정제
* **성과:** 약 203,000건의 독자적인 음악 데이터셋을 DB에 적재하여 외부 API 의존성을 완전 탈피하고 안정적인 추천 기반 확보

### 2️⃣ 다단계 동기 통신 및 AI 추론 연산 부하에 따른 응답 지연 개선
* **문제 배경:** [웹 브라우저 → Spring Boot → Flask AI → DB 필터링]으로 이어지는 다단계 통신 및 AI 연산 부하로 인해 로딩 지연 현상 발생
* **원인 분석:** 분산 서버 간 동기 요청 처리 방식 및 AI 추론 연산 대기 시간, DB 오디오 피처 조건절 쿼리의 복잡도
* **해결 방안:** 
  1. 오디오 피처 7개 변수에 대한 DB 파라미터 검색 쿼리 및 인덱싱 구조를 최적화하여 백엔드 필터링 연산 속도 개선
  2. AI 추론 처리 시간 동안 클라이언트 이탈을 방지하기 위해 Thymeleaf 기반 동적 라우팅 및 대기 UX 파이프라인 구축
* **성과:** 물리적 네트워크 및 연산 지연 상황에서도 시스템 안정성을 유지하고 사용자 경험(UX) 최적화

### 3️⃣ AI 모델 성능 향상을 위한 데이터 희소성 극복 및 8.6만 건 데이터셋 구축
* **문제 배경:** 10가지 감정 클래스 분류 시 단일 오픈소스 데이터셋의 데이터 희소성 및 불균형으로 인해 특정 감정 예측 편향 발생
* **원인 분석:** 실제 일상 구어체 학습 데이터의 부족으로 인한 AI 모델 일반화 성능 저하
* **해결 방안:** AI 허브 감성 대화 말뭉치와 HuggingFace 데이터셋, 자체 수집 일상 대화 데이터를 복합 융합하여 총 86,600건의 정제된 학습 파이프라인 완성
* **성과:** 전체 정확도 77.4% 달성 및 희귀 감정 클래스 Macro F1-Score 82.8% 확보를 통해 정교한 추천 백엔드 파이프라인 완성
